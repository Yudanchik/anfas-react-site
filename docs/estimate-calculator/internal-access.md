# Доступ администратора

## Реализация для REG.RU

Сайт остаётся статическим React-приложением. Проверка администратора выполняется сервером PHP, а не паролем в JavaScript. Публичной регистрации, базы пользователей и восстановления пароля нет. Ссылка на смету удалена из публичной шапки, страница помечена noindex, аналитика на внутреннем маршруте отключена.

После проверки PHP-сессии браузер загружает калькулятор. Его JS/CSS собираются в `assets/estimate-private/`; правила корневого `.htaccess` направляют запросы этих файлов в `api/estimate-asset.php`, который проверяет ту же сессию. Без настроенного администратора вход закрыт, а код калькулятора без сессии не должен отдаваться.

Сессия cookie `anfas_estimate`: HttpOnly, SameSite=Strict, Secure при HTTPS, смена ID после входа, 30 минут неактивности, абсолютный срок 8 часов. POST требует CSRF-токен. После 10 попыток с одного IP за 15 минут вход ограничивается; общий лимит — 100 за то же окно. Пароль хранится только как `password_hash`.

Автоматические unit/PHP-тесты калькулятора **удалены по решению владельца**. CI gate сейчас: `pnpm check` и `pnpm build`. Исторические прогоны тестов не являются текущим CI gate.

## Что доставляет CI/CD автоматически

После merge в `dev` (стенд) или `main` (production) сборка выкладывает, среди прочего:

| Артефакт | Назначение |
|----------|------------|
| `api/estimate-auth.php` | Вход, проверка сессии, выход |
| `api/estimate-session.inc.php` | Общая логика сессии / CSRF / rate limit (прямой URL запрещён) |
| `api/estimate-asset.php` | Выдача private JS/CSS только при сессии |
| `api/estimate.config.example.php` | Пример конфига **без** секретов |
| `assets/estimate-private/*` | Закрытый код калькулятора |
| корневой `.htaccess` | rewrite private assets, SPA fallback для `/internal/estimate`, deny `*.local.php` / `*.inc.php` / `*.example.php` |

Существующие `api/lead.php`, `api/price-download.php` и их конфиги **не перезаписываются** секретами из Git. Workflow исключает `api/*.local.php` из артефакта и FTP (и `config.local.php`, и `estimate.config.local.php`).

Пути вида `www/dev.anfas-remont.ru/api/` в панели файлового менеджера — **пути панели**, не подтверждённые абсолютные пути ОС. Каталог для rate limit задайте по фактическому пути хостинга вне web root.

## Что создать один раз вручную (отдельно для dev и prod)

На **каждом** стенде отдельно:

1. PHP 8.0+, HTTPS, поддержка `.htaccess` / `mod_rewrite`. Не размещайте калькулятор там, где PHP отдаётся как исходный текст.
2. **Приватный writable-каталог вне корня сайта** для счётчиков попыток входа (права только у процесса сайта). Путь возьмите из панели REG.RU / SSH, не из примеров в документации.
3. Файл **`api/estimate.config.local.php`** по образцу `estimate.config.example.php`:
   - `username` — логин администратора;
   - `password_hash` — хеш пароля;
   - `session_version` — случайная строка ≥ 32 символов;
   - `rate_limit_path` — абсолютный путь к приватному каталогу из п.2;
   - `allow_local_http` — `false` на стендах.
4. Файл с секретами **не** класть в Git и **не** присылать в чат. Деплой не должен его удалять (exclude `api/*.local.php`).

Строже: весь конфиг вне web root + переменная окружения сервера `ANFAS_ESTIMATE_CONFIG` с абсолютным путём к файлу.

### Как получить `password_hash` безопасно

В доверенной PHP-консоли на своей машине или на сервере (не в URL и не в чате):

```php
echo password_hash('ваш-длинный-пароль', PASSWORD_DEFAULT);
```

Вставьте только результат в `password_hash`. Не коммитьте пароль и хеш.

### Смена логина / пароля и отзыв сессий

1. Сгенерируйте новый хеш (и при необходимости новый `username`).
2. Обновите `estimate.config.local.php` на стенде.
3. Задайте **новый** `session_version` — все старые сеансы сразу станут недействительными.

Саморегистрации и ролей сотрудников нет: один администратор.

## Поведение без конфига

Если `estimate.config.local.php` отсутствует или невалиден, `estimate-auth.php` отвечает ошибкой настройки (доступ закрыт). Private assets без сессии должны давать **401**, а не содержимое JS/CSS.

## Проверка после размещения на хостинге

Обязательно на **реальном** REG.RU (локальный `pnpm preview:estimate` не доказывает Apache rewrite):

- В приватном окне `/internal/estimate` — форма входа; до входа закрытый JS не загружается.
- Прямой URL `assets/estimate-private/calculator-*.js` без cookie → **401**.
- Неверный пароль → отказ; верный → калькулятор.
- Cookie `anfas_estimate`: Secure, HttpOnly, SameSite=Strict; ответы auth/assets — `Cache-Control: no-store`.
- Прямые запросы `*.local.php`, `*.inc.php`, `*.example.php` запрещены.
- После выхода private файл снова **401**.
- Публичные страницы и прайс работают без входа.
- Если статику отдаёт **nginx мимо Apache**, правила `.htaccess` могут не применяться: тогда private URL нужно закрыть на уровне nginx/прокси или убедиться, что PHP-gate всё равно вызывается.

## Локальная разработка и проверка PHP

Два разных режима:

| Режим | Команда | Вход |
|-------|---------|------|
| **Разработка UI** | `npm run dev` / `pnpm dev` → `/internal/estimate` | Автоматически (только Vite, `import.meta.env.DEV`). PHP не нужен. |
| **Проверка как на стенде** | `pnpm build` → `pnpm preview:estimate` | Настоящий PHP-логин; пароль в терминале. Нужен PHP 8+. |

На **dev/production** сборка всегда с `DEV=false`: обхода нет, нужен `estimate.config.local.php` и логин/пароль.

### Ежедневная работа над калькулятором

```bash
npm run dev
# открыть http://127.0.0.1:5173/internal/estimate
```

В шапке сессии будет «Смета · Локальная разработка». HMR работает как обычно.

### Перед выкладкой / проверка защиты

```bash
pnpm build
pnpm preview:estimate
# http://127.0.0.1:4178/internal/estimate + логин/пароль из терминала
```

Docker/nginx в репозитории без PHP закрывает `/assets/estimate-private/` и `*.php` с 404.

## Границы защиты

Сметы и PDF живут на устройстве администратора (localStorage / скачивание). Сеанс защищает доступ к инструменту через сайт, но не шифрует локальные файлы. На общем ПК — отдельный профиль браузера и очистка данных.

Старые публичные calculator chunks на хостинге после первой выкладки с private-раздачей удалите после сверки. Не удаляйте серверные `*.local.php` и приватные PDF прайса.
