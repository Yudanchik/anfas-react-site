# План: актуализация сметы по PDF и шаблон прайс-листа

**Статус:** план. Код калькулятора пока не меняем.  
**Дата:** 2026-09-10  
**Рабочий backlog для утверждения:** [stage-a-price-coverage-sheet.md](./stage-a-price-coverage-sheet.md)

---

## Цель

1. Сверить калькулятор с PDF-прайсом Anfas и найти **недостающие labour-only** работы.  
2. Дополнить текущие разделы: **Полы / Стены / Потолки / Плитка / Электрика / Сантехника**.  
3. После актуализации дать пользователю **шаблон прайс-листа в XLSX**: скачал → поправил названия/цены → загрузил XLSX → калькулятор считает по его прайсу; сценарии держатся на `work_id` / `scenario_role`, не на названии.

## Правила (не менять)

| Правило | Смысл |
|---------|--------|
| **PDF = SoT для Anfas** | `resources/source-documents/anfas-price-2026.pdf` — источник работ и цен **встроенного** Anfas-прайса (не формат пользовательского импорта) |
| **Только работы** | Материалы, товары, изделия, выезды, коэффициенты и спорные «работа+материал» **не** добавляем |
| **6 текущих разделов** | Не раздувать план новыми вкладками (ГКЛ, Грильято, отопление и т.п.) — вне этой задачи |
| **Шаблон / импорт = только XLSX** | Download и upload пользовательского прайса — **XLSX по нашему шаблону**. PDF и CSV как импорт прайса в MVP **не** поддерживаем |
| **Стабильные id** | Сценарии опираются на `work_id` / `scenario_role`, не на отображаемое название |
| **Пользовательский прайс** | Только наш XLSX-шаблон; чужой произвольный Excel/PDF не принимаем |

Текущие counts mapping: **95 / 57 / 35 / 55 / 159 / 163** (полы…сантехника). Это whitelist работ, не весь PDF (~1500+ строк).

### Утверждённый формат прайса (owner)

| | Решение |
|--|---------|
| Формат шаблона | **только XLSX** |
| Формат загрузки | **только XLSX** |
| PDF как пользовательский импорт | **нет** — у компаний разная вёрстка таблиц; надёжно сопоставить работы/цены/единицы нельзя |
| CSV в MVP | **нет** — нельзя удобно скрыть/защитить системные ключи сценариев |
| CSV позже | possible future/export, **не** текущий план |
| Хранение MVP | client-side / localStorage; **на сервер прайс не загружаем** |

**Пользователь может менять:** название работы, цену, активность строки, комментарий.  

**Пользователь не должен менять (служебные поля):** `work_id`, `section`, `group`, `unit` для сценарных работ, `scenario_role`, `line_kind`.  
В XLSX эти поля — **скрытые/служебные**, чтобы лист выглядел как обычный прайс, а не техтаблица.

**Сценарии:** смена названия не ломает сценарии. Повреждённый/удалённый `work_id` у обязательной сценарной работы → ошибка импорта / блок применения профиля. Строки без `work_id` (если когда-либо появятся) — только через «Добавить из прайса», не в сценариях.

## Этапы

### Stage 1 — Audit labour-only gaps

- Сверить PDF с `*_PRICE_MAPPING` по 6 разделам.  
- Отметить: уже есть / добавить / только alias (другое имя) / не брать (материал, комплекс, вне раздела).  
- **Сделано:** curated sheet → [stage-a-price-coverage-sheet.md](./stage-a-price-coverage-sheet.md).

### Stage 2 — Approve backlog

Владелец утверждает sheet (или сокращает до P1):

- что **add_now**;  
- что только **alias** (title/цена);  
- что **не** добавляем.

Без approve mapping не правим.

### Stage 3 — Update calculator

- **P1 сделано (2026-09):** +32 labour в Плитка/Полы/Стены/Сантехника; alias title/price где нужно; электрика/потолки без расширения UX; сценарии default не раздувались (price-add).  
- Backlog: [stage-a-price-coverage-sheet.md](./stage-a-price-coverage-sheet.md).  
- Далее: Stage 4–5 (XLSX шаблон/импорт), не смешивать с P2 mapping без отдельного approve.

**Не делаем** в mapping-этапе: импорт прайса, новые вкладки, серверное хранение прайса.

### Stage 4 — Шаблон прайс-листа (download) · XLSX only

- Кнопка **«Скачать шаблон»** → файл **`.xlsx`** (не CSV, не PDF).  
- Содержимое = актуальный Anfas labour-каталог после Stage 3.  
- **Видимые колонки (для пользователя):** название, цена, активность, комментарий (+ при необходимости единица как read-only display).  
- **Скрытые служебные колонки:** `work_id`, `section`, `group`, `unit` (для сценарных — защищён/не для правки), `scenario_role`, `line_kind`.  
- Краткая инструкция на листе/в docs: править можно название и цену; системные ключи не трогать — от них зависят сценарии.  
- Защита листа/столбцов (по возможности в Excel): скрыть служебное, не ломать структуру при обычном редактировании цен.

### Stage 5 — Upload / import / validation · XLSX only

- **«Загрузить прайс-лист»** — только `.xlsx` нашего шаблона; иные форматы (PDF, CSV, произвольный Excel) — отказ с понятным сообщением.  
- Разбор **client-side**; профиль в **localStorage**; **на сервер не отправляем**.  
- Валидация:
  - файл читается как наш шаблон (есть служебные ключи);
  - цены ≥ 0, конечные числа;
  - `work_id` уникальны среди активных labour-строк;
  - `section` / `line_kind` из допустимого набора;
  - для **обязательных сценарных** ролей: `work_id` + `scenario_role` на месте — иначе **ошибка / блок Apply**;
  - смена **названия** допускается и **не** ломает сценарии;
  - строки без `work_id` (если есть) → только price-add, не сценарии; предупреждение в отчёте.
- Отчёт ошибок + preview (diff цен/названий) + confirm Apply.  
- Активный профиль: builtin Anfas или загруженный XLSX; смета хранит `priceProfileId` / hash, чтобы старые копии не пересчитывались молча.  
- Сценарии: **`scenario_role` → `work_id` → цена/title из профиля**; без автоподбора по русскому названию; missing role → «сценарий частично недоступен».

### Stage 6 — QA / docs / review

- Прогон: вход → сценарии → price-add → скачать XLSX → изменить название/цену → загрузить → сценарий жив → смета.  
- Негативные кейсы: загрузка PDF/CSV; битый `work_id` у сценарной строки; чужой xlsx.  
- Docs: customer-workflow + раздел «Свой прайс (XLSX)».  
- *(Отдельно: выгрузка **сметы** клиенту PDF/CSV — продукт сметы, не формат прайса.)*  
- Review владельца.

## Что сознательно вне плана

- Новые разделы сайта (ГКЛ, подвесные потолки, отопление, двери…).  
- Материалы и комплексы без разделения.  
- Импорт прайса из **PDF** или **CSV** (CSV — только possible future/export, не MVP).  
- Backend-хранилище прайсов / синхронизация устройств.  
- Автореализация без approve Stage 2.

Кратко зафиксированные решения по объёму актуализации (не раздувать 6 вкладок): см. шапку [stage-a sheet](./stage-a-price-coverage-sheet.md).
