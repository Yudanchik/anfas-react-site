# Развёртывание прайс-листа на существующем хостинге REG.RU

Практический чек-лист для случая, когда на сервере **уже есть рабочий**
`public/api/config.local.php` и через него уже отправляются обычные заявки
сайта (`intent` ≠ `price-list`). Документ описывает, как **расширить** этот
файл для поддержки прайс-листа, не ломая уже работающую форму.

Как устроен сам механизм (HMAC-ссылка, TTL, dual-mail, замена PDF, откат) —
подробно в [`docs/PRICE_LIST.md`](PRICE_LIST.md), здесь это не повторяется.
Настройка SMTP/Mail.ru «с нуля» — в [`docs/LEAD_FORM_EMAIL.md`](LEAD_FORM_EMAIL.md).

## 1. Результат проверки кода (изменений не потребовалось)

Проверены `public/api/lead.php` и `public/api/price-download.php`:

- Оба файла читают конфигурацию только из одного источника —
  `require __DIR__ . '/config.local.php'` — без обращения к переменным
  окружения, константам или другим файлам.
- Все параметры, необходимые для прайс-листа
  (`price_pdf_path`, `price_link_secret`, `price_link_ttl`, `public_site_url`,
  `price_rate_limit.max_requests`, `price_rate_limit.window_seconds`,
  `price_rate_limit.storage_path`), уже читаются кодом через `$config[...] ?? ...`
  с безопасными значениями по умолчанию (пустая строка / `0`) — код уже
  полностью поддерживает эти параметры.
- Если один из обязательных параметров прайс-листа пуст — `buildPriceDownloadLink()`
  и `price-download.php` корректно возвращают `503` без падения и без утечки
  внутренних деталей.
- Ветка обычной заявки (`intent` ≠ `price-list`) вообще не обращается к
  `price_*`-ключам конфигурации — добавление новых ключей в `config.local.php`
  никак не затрагивает её работу.

**Вывод:** код `lead.php` и `price-download.php` менять не потребовалось.
Задача решается добавлением уже поддерживаемых ключей в существующий
`config.local.php` на сервере. Файлы `public/api/lead.php`,
`public/api/price-download.php`, `public/api/config.example.php` в рамках
этой задачи не менялись.

## 2. Параметры, которые уже есть в рабочем `config.local.php`

Не трогать значения этих ключей — от них зависит уже работающая форма
обратной связи:

| Параметр | Назначение |
|---|---|
| `to` | Ящик, куда приходят все заявки (в т.ч. прайс-листа). |
| `from` / `from_name` | От чьего имени уходят письма. |
| `smtp.enabled` / `smtp.host` / `smtp.port` / `smtp.encryption` / `smtp.username` / `smtp.password` | Доступ к SMTP Mail.ru, общий для всех писем сайта. |
| `min_submit_seconds` | Антибот-проверка минимального времени заполнения формы. |

## 3. Параметры, которые нужно добавить

Эти ключи в текущем `config.local.php` на сервере отсутствуют (форма прайс-листа
их ещё не получала) и должны быть добавлены в тот же массив:

| Параметр | Тип | Назначение |
|---|---|---|
| `price_pdf_path` | `string` | Абсолютный путь на файловой системе сервера к боевому PDF прайс-листа. Используется только `price-download.php`. |
| `price_link_secret` | `string` | Случайный секрет для HMAC-подписи ссылки на скачивание. Минимум 32 символа, свой для каждого окружения (prod ≠ dev). |
| `price_link_ttl` | `int` | Срок жизни ссылки на скачивание, в секундах. Ориентир — `86400` (24 часа). |
| `public_site_url` | `string` | Публичный адрес сайта (без завершающего `/`) — нужен `lead.php`, чтобы собрать абсолютную ссылку на `price-download.php` в письме клиенту. |
| `price_rate_limit.max_requests` | `int` | Сколько заявок на прайс-лист разрешено с одного IP за `window_seconds`. Ориентир — `5`. |
| `price_rate_limit.window_seconds` | `int` | Длина окна ограничения частоты, в секундах. Ориентир — `3600`. |
| `price_rate_limit.storage_path` | `string` | Writable-каталог вне web root для файловых счётчиков rate limit. |

Подробное описание механизма и требований к каждому параметру — в
[`docs/PRICE_LIST.md`, раздел 3](PRICE_LIST.md#3-параметры-configlocalphp).

## 4. Пример итогового `config.local.php` (уже существующее + новое)

```php
<?php
return [
  // --- Уже существует и работает — не менять ---
  'to' => 'anfas-remont@mail.ru',
  'from' => 'anfas-remont@mail.ru',
  'from_name' => 'Сайт Анфас',
  'smtp' => [
    'enabled' => true,
    'host' => 'smtp.mail.ru',
    'port' => 465,
    'encryption' => 'ssl',
    'username' => 'anfas-remont@mail.ru',
    'password' => 'УЖЕ_НАСТРОЕННЫЙ_ПАРОЛЬ_ПРИЛОЖЕНИЯ',
  ],
  'min_submit_seconds' => 2,

  // --- Новое: добавить для прайс-листа ---
  'price_pdf_path' => '/home/u1234567/private/anfas-price-list.pdf',
  'price_link_secret' => 'ВСТАВИТЬ_СЛУЧАЙНУЮ_СТРОКУ_ОТ_32_СИМВОЛОВ',
  'price_link_ttl' => 86400,
  'public_site_url' => 'https://anfas-remont.ru',
  'price_rate_limit' => [
    'max_requests' => 5,
    'window_seconds' => 3600,
    'storage_path' => '/home/u1234567/private/price-rate-limit',
  ],
];
```

`u1234567` — placeholder имени пользователя хостинга REG.RU, замените на
реальное (видно в панели REG.RU → «Хостинг» → «Доступы» → FTP, либо в текущем
пути `public_html`/`www` этого же аккаунта).

## 5. Где должен лежать PDF

Полный путь: `/home/<ваш-логин-хостинга>/private/anfas-price-list.pdf`.

Требования:

- Каталог `private` должен находиться **вне web root** сайта — то есть не
  внутри папки, которая указана как корень `anfas-remont.ru`
  (обычно `/home/<логин>/www/anfas-remont.ru/` или аналог, см.
  [`deploy/regru-hosting/README.md`](../deploy/regru-hosting/README.md)).
  Файл не должен открываться напрямую по `https://anfas-remont.ru/...`.
- Имя файла произвольное — важно, чтобы оно **дословно совпадало** со
  значением `price_pdf_path`.
- Если тариф REG.RU не позволяет вынести каталог за пределы web root —
  каталог обязателен к закрытию через `.htaccess` (`Require all denied` /
  `Deny from all`), как это уже сделано для `config.local.php`
  в `public/api/.htaccess`.
- Прод и dev-стенд используют **разные** файлы и пути (например,
  `/home/<логин>/private/anfas-price-list.pdf` для прода и
  `/home/<логин>/private-dev/anfas-price-list.pdf` для dev).

## 6. Права доступа

| Объект | Рекомендованные права | Почему |
|---|---|---|
| Каталог `private` (PDF) | `750` | Владелец (аккаунт хостинга/PHP) — полный доступ; группа — чтение/выполнение при необходимости; остальным — ничего. |
| Файл PDF | `644` (или `640`, если хостинг это поддерживает без проблем для PHP) | Должен быть читаем PHP-процессом (`is_readable()` в `price-download.php`); запись посторонним не нужна. |
| Каталог `price-rate-limit` | `750` | PHP-процесс должен иметь право **создавать и изменять** файлы-счётчики в этом каталоге (см. `fopen(..., 'c+')` в `lead.php`). |

На типичном shared-хостинге REG.RU PHP выполняется от имени владельца аккаунта
(то же, что и FTP-пользователь), поэтому после обычной загрузки по FTP права
чаще всего уже корректны — но их стоит явно проверить в файловом менеджере
после загрузки (пункт 1 чек-листа в разделе 7).

## 7. Полный тест после настройки

1. **Права и путь.** В файловом менеджере хостинга убедиться, что PDF лежит
   по пути из `price_pdf_path`, каталог не открывается напрямую по HTTP,
   файл помечен как читаемый.
2. **Обратная совместимость.** Отправить обычную заявку с сайта (не прайс-лист,
   например форму консультации) — убедиться, что она по-прежнему приходит на
   почту без ошибок. Это подтверждает, что добавленные ключи не сломали
   существующий сценарий.
3. **Заявка на прайс-лист.** На `/prices` (или любой странице категории)
   нажать «Получить полный прайс», заполнить имя/телефон/email, отправить.
4. **Письмо менеджеру.** Проверить `to` из `config.local.php` — письмо
   пришло с пометкой «Тип заявки: запрос полного прайс-листа» и корректными
   именем/телефоном/email заявителя.
5. **Письмо клиенту.** Проверить указанный в форме тестовый email (и папку
   «Спам») — пришло отдельное письмо со ссылкой на скачивание, читаемы и
   текстовая, и HTML-версия.
6. **Скачивание PDF.** Перейти по ссылке из письма клиента — должен начаться
   вопрос сохранить/скачать `anfas-price-list.pdf`; открыть файл и убедиться,
   что это актуальный боевой прайс.
7. **Проверка защиты (опционально, но рекомендуется на dev перед продом).**
   Изменить один символ в `id`/`exp`/`sig` ссылки → ожидается `403`.
8. **Проверка TTL (опционально на dev).** Временно поставить маленький
   `price_link_ttl` (например `30`), получить ссылку, подождать истечения,
   перейти по ней → ожидается `410`, затем повторно отправить форму и
   убедиться, что новая ссылка снова рабочая.
9. **Rate limit.** Отправить несколько заявок на прайс-лист подряд с одного
   IP сверх `price_rate_limit.max_requests` → должен появиться `429` без
   отказа для последующих заявок после окончания окна `window_seconds`.

Пункты 6–9 полностью совпадают с обязательным чек-листом после любой замены
PDF — см. [`docs/PRICE_LIST.md`, раздел 5.2](PRICE_LIST.md#52-обязательные-проверки-после-замены).

## 8. Что проверять при ошибках

| Симптом / ответ API | Вероятная причина | Что проверить |
|---|---|---|
| `503 Mail config is missing` | `config.local.php` не найден по пути `public/api/config.local.php` на сервере | Файл действительно лежит в папке `api/` рядом с `lead.php`; имя файла точное (без `.example`, без опечаток). |
| `503 Mail addresses are not configured` | Пустые `to`/`from` | Значения `to`/`from` в `config.local.php` (общая часть, не про прайс). |
| `503 Price list delivery is not configured` | Пустой/отсутствует один из `price_pdf_path`, `price_link_secret`, `public_site_url` | Все три ключа заполнены и не пустые строки; `price_link_ttl` больше `0`. |
| `429 Too fast` | Заявка отправлена быстрее `min_submit_seconds` | Это ожидаемая антибот-защита; повторить заявку через форму как обычный пользователь. |
| `429 Too many requests, try later` | Превышен `price_rate_limit.max_requests` за `window_seconds` с этого IP | Подождать окончания окна или скорректировать `price_rate_limit` под реальную нагрузку. |
| `502 Failed to send email` | Не отправилось письмо в офис (SMTP-ошибка) | Пароль приложения Mail.ru не истёк, `smtp.*` не менялись, хостинг не блокирует исходящий SMTP-порт 465/587. |
| `502 Заявку получили, но не удалось отправить письмо со ссылкой` | Письмо офису ушло, письмо клиенту — нет | Email клиента корректен и не отклонён почтовым сервером; те же SMTP-причины, что выше. Заявка всё равно зафиксирована офисом. |
| Ссылка → `400 Invalid link` | Ссылка обрезана/повреждена при копировании | Открыть ссылку из письма целиком, одним переходом, без ручного редактирования. |
| Ссылка → `403 Invalid link` | Подпись не совпадает (ссылка подделана или `price_link_secret` сменили после выдачи ссылки) | Не менять `price_link_secret` без необходимости; при плановой ротации — предупредить, что старые ссылки перестанут работать. |
| Ссылка → `410 Link expired` | Истёк `price_link_ttl` | Ожидаемое поведение; запросить прайс через форму ещё раз. |
| Ссылка → `404 File is not available` | `price_pdf_path` указывает не туда / файл удалён / нет прав на чтение | Путь в конфиге совпадает с реальным расположением файла; права на файл (раздел 6). |
| Ссылка → `503 Downloads are not configured` | Тот же `config.local.php` не найден или `price_link_secret`/`price_pdf_path` пустые на пути `price-download.php` | То же самое, что для `503 Price list delivery is not configured`. |

## 9. Полный сценарий развёртывания на REG.RU

1. Обычный деплой фронтенда без изменений: `pnpm build` → существующий
   GitHub Actions workflow → FTP → `build/client` (см.
   [`deploy/regru-hosting/README.md`](../deploy/regru-hosting/README.md)).
   Прайс-лист не требует отдельного релиза фронтенда для этой задачи.
2. Через FTP/файловый менеджер REG.RU открыть уже существующий и рабочий
   `api/config.local.php` на сервере (там же, где сейчас настроена обычная
   форма).
3. Добавить в возвращаемый массив новые ключи из раздела 3/4, не удаляя и не
   меняя существующие (раздел 2).
4. Сгенерировать `price_link_secret` — например, локально:
   `php -r "echo bin2hex(random_bytes(32));"` — и вставить получившуюся
   строку как значение. Не использовать пример из репозитория «как есть».
5. Убедиться, что каталог `private` (или аналогичный, вне web root) существует
   на сервере; если нет — создать через файловый менеджер REG.RU.
6. Загрузить боевой PDF прайс-листа в этот каталог **под именем**, указанным
   в `price_pdf_path`.
7. Убедиться, что каталог из `price_rate_limit.storage_path` существует и
   доступен на запись (или что PHP сможет создать его сам — `lead.php`
   создаёт каталог автоматически при первом запросе, если это возможно).
8. Проверить права по разделу 6.
9. Сохранить `config.local.php`.
10. Пройти полный тест из раздела 7.
11. Повторить шаги 2–10 отдельно для dev-стенда со своими значениями
    `price_pdf_path`, `price_link_secret`, `price_rate_limit.storage_path`,
    `public_site_url` — dev и prod не должны использовать общий секрет или
    общий путь к файлам (см. [`docs/PRICE_LIST.md`, раздел 3](PRICE_LIST.md#3-параметры-configlocalphp)).
