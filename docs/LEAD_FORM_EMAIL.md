# Заявки с сайта на почту (REG.RU + Mail.ru)

Сайт — статика (HTML/JS). Письма шлёт `public/api/lead.php` на хостинге.
Ящик получателя: `anfas-remont@mail.ru`.

## Как это работает

```
Форма на сайте
  → POST /api/lead.php
  → SMTP smtp.mail.ru
  → письмо на anfas-remont@mail.ru
```

## Шаг 1. Настроить Mail.ru (один раз)

1. Войдите в [mail.ru](https://mail.ru) как `anfas-remont@mail.ru`.
2. Откройте: **Все настройки → Безопасность**  
   (или [account.mail.ru](https://account.mail.ru) → Безопасность).
3. Включите доступ по **SMTP** / внешним приложениям.
4. Создайте **пароль приложения** (для «Почта» / «Другое»).
5. Скопируйте этот пароль — его вставите в `config.local.php`.  
   Обычный пароль от входа в mail.ru **не подойдёт**.

SMTP Mail.ru:

- host: `smtp.mail.ru`
- port: `465`
- encryption: `ssl`
- username: `anfas-remont@mail.ru`

## Шаг 2. Задеплоить код с формой и `api/lead.php`

Нужна ветка/деплой, где уже есть папка `api/` на сайте  
(после `pnpm build` она попадает в `build/client/api/`).

На проде должны открываться примерно так:

`https://ваш-домен.ru/api/lead.php`

(если PHP выключен — будет ошибка; в панели REG.RU проверьте, что PHP включён).

## Шаг 3. Создать `config.local.php` на сервере

Через FTP / файловый менеджер REG.RU в корне сайта (рядом с `index.html`)  
создайте файл:

`api/config.local.php`

Скопируйте содержимое из репозитория `public/api/config.example.php` и замените:

```php
'password' => 'СЮДА_ПАРОЛЬ_ПРИЛОЖЕНИЯ_ИЗ_MAIL_RU',
```

`to`, `from`, `smtp.username` уже можно оставить `anfas-remont@mail.ru`.

**Важно:** этот файл не коммитьте в git (он в `.gitignore`).  
На сервере он лежит только у вас.

## Шаг 4. Проверить

1. Откройте сайт на проде.
2. Отправьте тестовую заявку из формы.
3. Проверьте входящие `anfas-remont@mail.ru` (и «Спам»).

Тема письма будет вида: `Заявка с сайта Анфас — …`.

Локально (`pnpm dev`) PHP не работает — тест только после деплоя на REG.RU.

## Прайс-лист: второе письмо со ссылкой на PDF

Заявки с формы прайс-листа (`intent="price-list"`, страницы `/prices`,
`/prices/:categorySlug`) отправляют **два** письма вместо одного:

1. Обычное письмо в офис (`to` из `config.local.php`) — как описано выше, с
   пометкой, что это запрос полного прайса.
2. Дополнительное письмо **клиенту** на email, указанный в форме, со временной
   ссылкой на скачивание PDF.

Для второго письма в `config.local.php` нужны отдельные параметры
(`price_pdf_path`, `price_link_secret`, `price_link_ttl`, `public_site_url`,
`price_rate_limit`) — SMTP-доступ используется тот же, что и для обычных заявок.

Полная инструкция по параметрам, замене PDF, HMAC-ссылке, TTL и обязательным
проверкам после обновления файла — в [`docs/PRICE_LIST.md`](PRICE_LIST.md).

## Если письмо не приходит

1. `config.local.php` лежит именно в `api/` на сервере?
2. Пароль — именно **пароль приложения**, не от аккаунта?
3. PHP на хостинге включён?
4. В ответе формы на сайте есть ошибка? (откройте Network → `lead.php`)
