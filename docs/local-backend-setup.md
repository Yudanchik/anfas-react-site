# Локальный сайт + Strapi + NestJS

Проверенный этап от 28 сентября 2026 года. Любой зарегистрированный пользователь получает доступ к калькулятору. Личные кабинеты с серверным сохранением смет — следующий этап.

## Запуск после перезагрузки компьютера

Запустить Docker Desktop. Далее три отдельных терминала PowerShell, оставить каждый работающим.

Strapi:

```powershell
Set-Location 'C:\Users\1\Desktop\Работа anfas\anfas-cms'
pnpm db:up
pnpm develop
```

NestJS:

```powershell
Set-Location 'C:\Users\1\Desktop\Работа anfas\anfas-backend'
pnpm db:up
pnpm dev
```

Фронтенд:

```powershell
Set-Location 'C:\Users\1\Desktop\Работа anfas\anfas-react-site'
pnpm dev
```

Зависимости установлены. Существующие `.env` не перезаписывать. При новом клонировании бэкенда скопировать `.env.example` в `.env`, затем `pnpm install`.

## Настройки фронтенда

Локально создан gitignored `.env.local`:

```dotenv
VITE_AUTH_MODE=nest
AUTH_BACKEND_ORIGIN=http://127.0.0.1:3000
VITE_CONTENT_SOURCE=strapi
VITE_STRAPI_URL=http://127.0.0.1:1337
```

`/api/auth/*` проксируется Vite к NestJS. В браузере нет паролей администратора, серверных токенов Strapi или иных секретов. В `VITE_*` можно помещать только публичные настройки.

Текущая ветка ранее использовала только локальные репозитории контента. Адаптеры и схемы DTO перенесены из существующей `feature/strapi-journal-pilot`, подключены к текущим React Router loaders. CMS-режим читает опубликованные статьи, проекты, услуги, прайс и FAQ; изображения идут из Strapi uploads. При ошибке CMS включённый режим не подменяет ответ локальным контентом. Без `VITE_CONTENT_SOURCE=strapi` остаются локальные данные.

Старые `CONTENT_SOURCE`, `PROJECTS_CONTENT_SOURCE`, `STRAPI_URL` из прежнего `.env` текущим подключением не используются. В production-сборке контент фиксируется при prerender; изменения CMS требуют новой сборки. Локальный dev-сервер читает CMS при запросах страниц.

## Проверка пользователем

1. Открыть http://127.0.0.1:5173/auth.
2. Нажать «Нет аккаунта? Зарегистрироваться», указать email и пароль от 10 до 128 символов.
3. После регистрации автоматически открывается `/internal/estimate`. Ссылка «Смета» появляется в хедере, на мобильной ширине — в меню.
4. Обновить страницу: вход сохраняется.
5. Нажать «Выйти»: калькулятор скрывается, появляется форма входа.
6. Войти теми же данными: калькулятор доступен снова. Неверный пароль вызывает понятную ошибку.
7. Открыть журнал, проекты, услуги и прайс, проверить тексты и изображения. Главная и прайс также читают FAQ из CMS.

Не смешивать `localhost` и `127.0.0.1` в одном сеансе. Тестовый аккаунт `qa-local@example.test` оставлен только в локальной базе. Можно зарегистрировать свой аккаунт через интерфейс.

## Границы этапа

Сметы пока живут в localStorage браузера и не привязаны к аккаунту. Разные аккаунты в одном профиле браузера могут видеть общий черновик. Регистрация не требует подтверждения email; восстановления пароля пока нет.

Новый режим включается явно через `VITE_AUTH_MODE=nest`. Старый PHP-вход сохранён в `LegacyEstimateAccess` для существующего размещения; его прежний Vite-обход применяется только в legacy-режиме. В NestJS-режиме обхода входа нет.

Эта проверка относится к локальному Vite-серверу. Перед размещением на новом сервере нужно настроить HTTPS, production-базы/секреты/backup, reverse proxy для API и привести защиту private calculator assets к NestJS-сессии. Существующие PHP/Apache правила закрытых JS/CSS пока не заменены. Сервер не покупался и не настраивался.

## Размещение dev

Push фронтенда в `dev` запускает существующий workflow REG.RU только для environment `development`. Ветка `main` и production environment не используются. Локальный `.env.local` в Git не отправляется. Поэтому размещённый dev пока сохраняет прежние PHP-авторизацию и локальный контент: NestJS и Strapi ещё не размещены на сервере. Новый режим регистрации проверяется на http://127.0.0.1:5173; включать его на стенде нужно после настройки доступных HTTPS-адресов API/CMS и reverse proxy. Адреса 127.0.0.1 нельзя использовать как адреса сервисов на удалённом dev.
